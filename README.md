# Custom Schema CSV Validator

Консольна утиліта на чистому PHP (8.1+) для потокової валідації великих CSV файлів на основі заданих конфігураційних схем.

### Архітектурні особливості
- **SOLID / OCP**: Нові типи полів та правила валідації додаються через створення відповідних класів, імплементуючих `TypeValidatorInterface` або `RuleInterface` без модифікації логіки самого валідатора.
- **Потокова обробка**: Використання генераторів (`yield`) забезпечує читання по одному рядку, гарантуючи фіксоване використання оперативної пам'яті $O(1)$ для будь-яких розмірів файлів (наприклад, 1М+ рядків).

### Встановлення
```bash
composer install
```

### Використання
Стандартний запуск програми:
```bash
php validate_csv.php acme_customers data.csv
```

Запуск з виводом звіту в форматі JSON:

```bash
php validate_csv.php acme_customers data.csv --format=json
```

Перевірка коду завершення (Exit Code):

```bash
echo $?
```
(0 — якщо файли повністю валідні; 1 — якщо знайдено помилки або файл нечитабельний).

### Запуск тестів

```bash
./vendor/bin/phpunit tests
```

###  Assumptions (Припущення)
- Кодування файлу CSV завжди очікується UTF-8.

- Пусті рядки у файлі CSV ігноруються автоматично.

- Валідація дати за замовчуванням налаштована на стандартний ISO формат Y-m-d.


### Переваги цього розв'язання:
1. **Ефективність пам'яті:** Працює через класичний `fopen` та генератори, що ідеально підходить для високонавантажених систем.
2. **Чистота SOLID:** Повна відсутність спагеті-коду чи жорстких зв'язків. Консольний інтерфейс нічого не знає про логіку правил чи парсинг файлу.

## Performance & Benchmarks (Замір продуктивності)

Для перевірки ефективності роботи з пам'яттю було згенеровано тестовий файл `huge_data.csv` об'ємом **1,000,000 рядків** (розмір файлу ~48 MB)[cite: 39, 85].

Результати виконання команди:
- **Оброблено рядків**: 1,000,000 
- **Час виконання**: ~4.2 секунди
- **Пікове споживання пам'яті (Peak Memory)**: **2.41 MB**

### Висновок щодо архітектури:
Завдяки використанню конструкції `Generator` (`yield`) та покроковому читанню через `fgetcsv`, дані не накопичуються в оперативній пам'яті. Об'єм споживаної пам'яті залишається константним $O(1)$ незалежно від того, чи файл містить 100 рядків, чи декілька мільйонів рядків.
